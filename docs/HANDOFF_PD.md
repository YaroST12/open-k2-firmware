## PD engine facts (don't re-derive)

- `fusb302::caps()` = `g_engine.caps` (valid on every Source_Cap); `pd::active_caps()` wraps it
  (fake override for tests). Un-ACKed caps flood every ~154 ms (auto-crc off) -> source retries
  then hard-resets; `g_caps_acked = g_crc_on` at caps RX; TriggerPrep cycles CC while caps are
  un-ACKed. VbusWait: Ready = VBUS up + caps valid, timeout 5 s / 10 s attached
  (`include/k2/pd/pd_ccmode.hpp`).
- **Pinned-Rd (sink) boots:** `self_power_early` saves `g_boot_pin_rd`; `unit_detach()` calls
  `self_power_leave()`, `unit_attach()` and the run-over path call `self_power_restore()`
  (`include/k2/drivers/fusb302.hpp`). Fix `fd809b5`: before it, `rd_lines()` returned the pinned bits in
  sink boots, the charger never saw a detach, and every re-attach failed "no PD after re-attach"
  (0/17). Dropping Rd explicitly (SWITCHES0=0) is the working way to give the charger a detach, even in Rd modes.

## Quirks to remember (details in docs/CHARGER_QUIRKS.md)

- Xiaomi Mi Turbo auth (SVID 0x2717): sink-initiated opener `0x27170101`, charger drives
  `0x27170201..0x2717020A` (step-1 reply MUST be `0x27170102`), then re-announces PPS APDOs at
  6 A — but only when the cable e-marker is unreadable/real 6 A; over a 5 A-reading EPR cable the
  re-announce stays 5 A (`auth-capped-by-cable`). Known limitation: with proactive
  Discover-SVIDs REQ default-on, a scripted full run completes the chain mid-run and the row in
  flight fails "offers changed" (`/tmp/k2runs/c1-authed-full-run.log`); use `pd-reread` + `pdos` /
  `pd attach` to read unlocked offers instead.
- Spoof (builtin kind 2 `cuktech-240w`, `ecd43f6`): this board has NO Ra path on CC, so a charger
  never sends SOP' Discover Identity and the spoof never fires charger-side; spoofed identity
  does not unlock 6 A over a dumb cable (CHARGER_QUIRKS.md:113).

## Standards compliance check (2026-11-05, no device, code vs USB PD R3.2 v1.2)

Verified against `USB_PD_R3.2_V1.2_main_spec.txt`:
- All message type constants match Table 6.4 (control: Accept 3, Reject 4, PS_RDY 6, Get_Source_Cap 7,
  Get_Sink_Cap 8, Wait 12, Soft_Reset 13, Not_Supported 16, Get_Status 18, Get_Sink_Cap_Ext 22,
  Get_Revision 24), Table 6.5/6.6 data (Source_Cap 1, Request 2, Sink_Cap 4, EPR_Request 9, EPR_Mode 10,
  Revision 12) and extended (Status 2, Sink_Caps_Ext 15, Extended_Control 0x10, EPR_Source_Caps 0x11).
- RDO layouts match Tables 6.20-6.22 (fixed op/max current 10 mA bits 19:10/9:0; PPS 20 mV bits 20:9 +
  50 mA bits 6:0; AVS 25 mV bits 20:9; EPR bit 22; No-Suspend bit 24, USB-comm bit 25).
- Timers within spec table 7.1.8: tSenderResponse 50 ms < kAcceptMs 300; tPSTransition EPR max 1020 ms <
  kPsRdyMs 1500; tEnterEPR max 550 ms < kEprEnterMs 800; tSinkEPRKeepAlive 250-500 ms, kEprKeepAliveMs 400 in
  range; tSinkRequest 100 ms = kWaitRetryMs; tPPSRequest 10 s > kPpsKeepAliveMs 5000 (keep-alive OK).
- Chunked extended messages padded to 4-byte boundary for Data Size < 26 (Table 6.48) — matches
  `request_chunk()`.
- Unsolicited Source_Capabilities in EPR mode (§7.30.5, checked on branch k2/epr-caps): the rule binds the
  SINK (a Source_Capabilities that is not the answer to our Get_Source_Cap makes the sink start a Hard Reset;
  the source resets if the sink Requests against it). The old code re-requested instead. Fixed: `Sink`
  tracks `get_cap_sent_` (set when the Xiaomi step queues Get_Source_Cap); in EPR mode an unsolicited
  Source_Capabilities now Hard Resets and sets `resume_`, so the next announce gets a PDO 1 Request. SPR mode
  is unchanged. The CUKTECH re-announce after the auth unlock (hardware 2026-11-04) happened in SPR mode (that
  source has no EPR bit), so it never justified the EPR-mode deviation; there is no hardware evidence of an
  EPR-mode re-announce. Tests: `tests/test_pd_sink.cpp` (EPR unsolicited / solicited cases).
- Host suite: 130 binaries pass; `test_emlib` passes but is slow (>60 s, 13030 checks); `test_ui_extremes`
  fails 100 checks on clean main (text "4294967295/4294967295" render mismatch, tests/test_ui_extremes.cpp:40)
  — pre-existing, UI/readout, not PD.
