# UI work handoff (open-k2-firmware, 2026-11-05)

Continuation doc for agents picking up the K2 240x240 LCD UI rework. Read this, then
the local k2-micro-gui design notes (not in the repo; keep them updated when a design

## Repo / branch / ground rules

- Repo `open-k2-firmware`, branch `main` @ `d6a545d`. Never push.
- Untracked files `results.json` and `docs/charger-cards/` belong to the user — never touch.
- Commit heredoc always ends with:
  `Generated by Mistral Vibe.` + `Co-Authored-By: Mistral Vibe <vibe@mistral.ai>`
- **Build firmware ONLY via docker:** `make docker-build` (image `open-k2-builder:latest`,
  already built). The host has NO arm-none-eabi toolchain; do not download one.
- **Flash:** `python3 tools/k2_remote.py dfu --confirm`, then
  `python3 tools/k2_flasher.py flash build/open_k2.k2 --timeout 240`, then
  `python3 tools/k2_flasher.py reboot`. The bootloader handshake is flaky — `probe` and retry,
  or the user replugs holding MINUS for a clean DFU. K2 is on the FIRST USB-C port.
- **Host tests:** `make host-build/<test> -j8`, then run; loop over `host-build/test_*`
  (skip `*.out`). Disk is tight (~15 GB free) — don't clone toolchains or big artifacts.
- The user wants UI work delegated to k2-dev subagents one at a time (split code and tests
  between agents, medium effort model, close them when done). If a subagent stalls, the
  coordinator does the work directly — don't loop on stalled agents.

## Design invariants (decided, implemented)

- Canvas 240x240. The 20 px **button-label strip is attached to the physical button edge**
  (RIGHT edge of the board at MADCTL rotation 0, verified on hardware) via
  `orientation_for(rotation).edge` (0=Right,1=Top,2=Left,3=Bottom); boot default
  `kDefaultOrientation = {Right, 0}` (`d6a545d`). Labels are rotated text on vertical edges
  (`panel_text_dir`), readable when that edge is turned to the bottom. Never pair a rotation
  with a mismatched edge again — that bug shipped once.
- Host mockup canvas = bottom-strip 240x220 view = **rotation 3**, selected explicitly in
  `tests/test_ui_mockup.cpp` via `ui.configure_rotation(false, 3)`.
- Global chrome: 21 px top bar (`kBarH`), page name left + SNK/PAS boot-role badge
  (`fusb302::self_powered()`), right side `fmt3(V)xfmt3(A)` live readout (fixed 5-char slots,
  x152/x190, "OVR" on overflow) on every page EXCEPT Home, preceded by a static 10 px direction
  chevron in x140..149 (`BandRow::chevron`, physical direction, none when idle/stale); 1 px hairline
  at y `kBarH-1`.
- Home v7 "A - Dual hero" (no title bar, no footer): VBUS cell y0..69 and IBUS cell y72..141, each with a
  4 px status edge, a 64 px hero font (`kHero`, digits only, x39) over a faint trend sweep (110 columns x 2 px,
  4 column gap, cursor line; window 10s / 60s / 10m on OK short), the flow arrow (22 px box at x8,y101), the
  limit bar (x10..214, y136..138) and the near / over alarms (triangle, `NN% OF 5A`, inverted `OVER 5A LIMIT`).
  Band y144..193: W (font 48) | Wh over Ah. Info block y196..239: USB link + elapsed, protocol tag + value + role.
  Code: `src/ui/ui_home.cpp` (page), `home_model` (pure model), `home_cell` (compositor), `home_proto` (protocol
  row). The max text comes only from the contract / protocol and only in Live. OK long = energy reset.
- Sections separated by hairlines only — no section header text; protocol tags stay labeled;
  ChargerTest results sections are bare 2 px separators (`f3530fb`).
- Tools icons: 12x12 bitmaps generated `docs/ui_mockups/render_mockups.py` ICONS ->
  `tools/gen_icons.py` -> `src/ui/ui_icons.cpp` (`kIconCount` 16); Tools rows = icon x8 + name x26.
- Logical content is ALWAYS `{0,0,224,240}` (`ctx_.content`); `ContentViewport` maps it onto
  the physical content box. Never change it.
